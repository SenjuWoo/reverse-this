# Standalone installation and updates

Reverse THIS!, the [Starter Bundle](https://github.com/SenjuWoo/Ultimate-AI-Starter-Bundle) and [Skyrim Forge](https://github.com/SenjuWoo/SkyrimForge) have independent installers. None is a required parent installation. The bundle is useful for common compilers, AI providers and skills; Forge supplies Skyrim authoring and validation. This workbench supplies REA and analysis tools. Installing it never edits AI-provider settings, trust or credentials. The ownership matrix is in [README § Modular composition](../README.md#modular-composition); the bundle's [companion architecture](https://github.com/SenjuWoo/Ultimate-AI-Starter-Bundle/blob/main/docs/COMPANION-ARCHITECTURE.md) is the shared cross-repo contract.

Run `Install-Modkit.ps1` for the catalog or use `-Only rea`, `-Only jadx`, or another catalog ID for the current task. Normal installation resolves current owned pip, npm and NuGet packages as well as release tools. Intentional pins remain pins: REA uses 6.8.0 and its npm integrity; capa uses a matched package/rules/signatures release. A numerically newer valid owned tool is retained. Unknown release labels require their recorded identity rather than an invented ordering.

## Overlap and synchronization

Overlap is allowed only when one owner is clear. A consumer detects a shared tool or runtime first, compares its version and payload health, then reuses a current copy, updates an older owned copy in place, or preserves a newer or unknown copy and reports it. It does not silently reinstall or create a parallel copy.

- Kit-owned tools use `.kit-ok`, `.kit-record.json` and payload hashes. A current marker is skipped; an older one is updated; `-NoUpdate` keeps valid installed bytes; `-Force` is the explicit reinstall.
- Shared runtimes (`UABS_PYTHON`, Node, Java, .NET) are detected before installation. A missing prerequisite is installed once; a working existing one is reused rather than duplicated, and an explicitly bound incompatible interpreter is reported instead of replaced.
- External tools require `-ToolDirectories` or `UABS_TOOL_ROOTS` with a valid owner receipt; there is no drive scan. Unknown or unverified copies are preserved and reported.
- 7-Zip and DirectXTex are this kit's payloads. Forge may reference `sandbox/bin/7z.cmd` and the DirectXTex tools instead of installing a second copy.

The registered `%LOCALAPPDATA%\ReverseThis\kit.json` identifies the one canonical owner kit. Another source checkout uses that owner's sandbox and shims, with the new checkout's catalog/installer. It does not silently move the pointer or install another tool suite. An invalid pointer fails with its cause. `-InstallRoot "<absolute isolated root>"` deliberately isolates tool state and never writes the shared pointer; use this for tests. The installer log is `<owner>/sandbox/log/modkit.log`; `-DebugLog` includes package/archive details.

Shared Python resolves `UABS_PYTHON` in Process, then User scope, then validated base interpreters on PATH and the official manager's documented user locations. Virtual environments and AI-app runtimes are excluded. Existing manager-owned Python receives a patch update on its current feature line, never a feature-version replacement. Missing compatible Python uses the official `Python.PythonInstallManager` winget package, then `pymanager install --yes default`. Dependencies remain in tool venvs. An explicitly bound incompatible interpreter is reported rather than silently replaced.

Node and npm must be a compatible pair in the same shared installation. ASAR requires Node 22.12+; REA 6.8.0 requires ^22.23.4, ^24.22.1 or >=26.12.1. Generated npm shims bind the selected Node directory even if the caller's PATH starts with another Node. Existing winget-owned Node LTS at the standard installation path receives its targeted `OpenJS.NodeJS.LTS` update. Missing Node uses that official package. A working incompatible installation whose owner cannot be established is preserved and reported; a parallel runtime is not installed. Java and .NET retain the existing official winget prerequisite routes.

`-NoUpdate` retains valid installed packages and skips shared-runtime patch updates; missing selected tools can still install. `-Force` explicitly reinstalls and cannot be combined with `-NoUpdate`. `-Plan` prints the catalog without network or writes. `-Doctor` and `-Offline` inspect owner receipts/files without network, runtime setup or writes. Doctor does not prove target compatibility. Normal updates retain payload/state backups and roll back failed replacements.

For an already owned tool outside the canonical sandbox, supply its directory with `-ToolDirectories "<directory>"`. A 1.4 owner `.kit-record.json` must identify the catalog ID/version and bind shim/package metadata to file hashes. The installer validates it without running a GUI, then reuses and updates that same directory with retained backups. Explicit `UABS_TOOL_ROOTS` candidates are checked only at the root, `<root>/<catalog-id>` and `<root>/sandbox/tools/<catalog-id>`; there is no drive scan. Unverified legacy receipts are reported and preserved. Receipt hashes cover the named launchers/package metadata or one source representative; they are not a signature of every payload byte.

A compatible same-major REA already on PATH is reused as unowned with its observed version and launcher hash. Unknown, older or incompatible unowned REA is preserved and reported for its owner's update/verification, rather than duplicated. `-Force` is the explicit choice to install an isolated owned copy. Automatic in-place updates apply only where ownership is known; an arbitrary external file never grants update authority.

For a released ZIP installation, run `Update-ReverseThis.ps1`. It selects the official current source ZIP, requires its GitHub SHA-256 asset digest, validates the extracted release receipt and updates only public source paths. It verifies the previous `RELEASE.json` before replacement, refuses locally changed public files or new-path collisions, and retains prior source files under `sandbox/backups/source-*`. Private sandbox work/tools/state stay in place. Git development roots and linked write destinations are refused; review and fast-forward those through Git instead.

`-Destination <absolute directory>` (alias `-KitRoot`) selects an existing released kit or a missing/empty fresh source destination. A nonempty directory without a valid existing release is preserved. `-Archive <zip> -Sha256 <expected digest>` handles an independently verified local artifact, including bootstrapping 1.3 with the updater extracted from a verified 1.4 archive. `-Plan`, `-NoUpdate` and `-Offline` disable source updates without downloads or writes. Logs are `sandbox/log/source-update.log`; `-DebugLog` adds the selected release/commit/path details. Invalid fresh archives fail before creating the destination. A failed fresh deployment can leave its diagnostic sandbox; preserve those logs and select a clean destination for retry.

Run the deployed `Install-Modkit.ps1` after source deployment. A first normal run without `-InstallRoot` registers the new canonical owner. To refresh only an existing kit's installed choices, pass its `installed.json` tool IDs through `-Only id1,id2`; omitting `-Only` selects the full current catalog. `-InstallRoot` isolates tool state and never deploys source or registers a canonical owner. No updater or wrapper should guess catalog contents or rewrite the installed choices.
